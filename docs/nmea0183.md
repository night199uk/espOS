# NMEA 0183 input

`espos_nmea0183` reads NMEA 0183 sentences off a UART, checks them, decodes
the ones a GPS, a compass, a depth sounder and a log talk, and publishes what
they say to Signal K. A cheap GPS module on a dinghy, the depth sounder of a
boat that never got NMEA 2000, an old fluxgate compass: each becomes a source
on any espOS device.

It comes in three layers, and each is usable without the others:

* **The sentences** (`espos_nmea0183.h`, pure C): line assembly, checksum,
  fields, and decoders for GGA, RMC, VTG, HDT, HDM, HDG, DPT, DBT, DBS, DBK,
  MTW, VHW, ZDA and GST. No IDF dependency, so all of it runs in the host tests.
* **The UART** (`espos_nmea0183_uart.h`): a task per port, feeding every
  good sentence to up to `ESPOS_NMEA0183_UART_MAX_LISTENERS` (4) listeners,
  so one GPS can feed Signal K, a log file and a bridge at once.
* **Signal K** (`espos_nmea0183_sk.h`): what a sentence means as Signal K
  values. The mapping is pure C; the publisher hands it to `espos_sk`.

It is optional, so a project names it:

```cmake
espos_project_prologue(NAME "my_gps" COMPONENTS espos_nmea0183)
```

The Signal K layer publishes through `espos_sk`, which every project built
with the espOS prologue has. A component that uses `espos_nmea0183` on its
own adds `espos_sk` to its `REQUIRES` to publish; without it
`espos_nmea0183_sk_publish()` returns `ESP_ERR_NOT_SUPPORTED` and only the
mapping is there.

## A GPS in ten lines

```c
#include "espos.h"
#include "espos_nmea0183_sk.h"
#include "espos_nmea0183_uart.h"

static void on_sentence(const char *raw, const espos_nmea0183_sentence_t *s, void *arg)
{
    espos_nmea0183_sk_publish(s, true); /* true: a fix also sets the clock */
}

void app_main(void)
{
    ESP_ERROR_CHECK(espos_start(NULL));
    const espos_nmea0183_uart_cfg_t cfg = {.uart_num = 1, .rx_gpio = 5, .tx_gpio = -1, .baud = 9600};
    espos_nmea0183_uart_t gps;
    ESP_ERROR_CHECK(espos_nmea0183_uart_open(&cfg, &gps));
    espos_nmea0183_uart_add_listener(gps, on_sentence, NULL);
}
```

The whole example is
[`nmea0183_gps`](https://github.com/signalk-espOS/espOS/tree/main/components/espos_nmea0183/examples/nmea0183_gps).

Listeners run on the port's task. Copy what you need and return, and do not
call another `espos_nmea0183_uart_*` function from inside one: the port holds
its lock while listeners run, which is what lets `remove_listener()` promise
that a removed listener is not running any more.

## Wiring

| Talker | Signal | Into the ESP32 | `baud` | `invert_rx` |
|---|---|---|---|---|
| 3.3 V GPS module (u-blox NEO-6M/M8N/M10, ATGM336H) | TTL, 3.3 V | straight onto the RX pin | 9600 | no |
| Marine NMEA 0183 talker (sounder, compass, plotter) | RS-422, A and B | through an RS-422/RS-485 receiver (MAX3485, SN65HVD3082) | 4800 | no |
| Older single-ended talker (NMEA 0183 1.x, "RS-232") | one wire against ground | through a level shifter (MAX3232) or a receiver | 4800 | yes, when wired without an inverting shifter |
| AIS receiver, "high speed" 0183 | RS-422 | through a receiver | 38400 | no |

A marine talker never goes straight onto a pin: RS-422 swings beyond the
chip's 3.3 V. Many ESP32 boards made for this (the LilyGO T-CAN485 is one)
already carry an RS-485 transceiver, which listens to an RS-422 talker as it
is. A board with a single-ended talker and no inverter in between reads only
garbage and bad checksums; `invert_rx` flips the pin in the UART instead of
adding a chip.

Keep the console's UART free: UART0 is the console on most boards, so use 1
or 2. Pins follow the [sensor pin table](sensors.md#pins-are-arguments-never-defines);
on a Waveshare P4 panel stay off GPIO 14 to 19.

## What reaches Signal K

The paths are the ones signalk-server's own NMEA 0183 parser writes for the
same sentences, so a GPS on an espOS device and the same GPS on the server's
serial port look identical in the data browser.

| Sentence | Signal K paths |
|---|---|
| GGA | `navigation.position`, `navigation.gnss.methodQuality`, `.satellites`, `.horizontalDilution`, `.antennaAltitude`, `.geoidalSeparation` |
| RMC | `navigation.position`, `navigation.courseOverGroundTrue`, `navigation.speedOverGround`, `navigation.magneticVariation`, `navigation.datetime` |
| VTG | `navigation.courseOverGroundTrue`, `navigation.courseOverGroundMagnetic`, `navigation.speedOverGround` |
| HDT | `navigation.headingTrue` |
| HDM, HDG | `navigation.headingMagnetic` (HDG: the sensor plus its deviation), `navigation.magneticVariation` (HDG) |
| DPT | `environment.depth.belowTransducer`; with a positive offset also `surfaceToTransducer` and `belowSurface`, with a negative one `transducerToKeel` and `belowKeel` |
| DBT, DBS, DBK | `environment.depth.belowTransducer`, `belowSurface`, `belowKeel` |
| MTW | `environment.water.temperature` |
| VHW | `navigation.speedThroughWater`, and the headings when they are filled in |
| ZDA | `navigation.datetime` |
| GST | nothing: Signal K has no path for a position error, so `espos_nmea0183_decode_gst()` gives it to the firmware (a logger weighting its soundings by `h_accuracy`) |

Everything is in Signal K units: radians, metres, m/s, kelvin.

**Nothing is published that the sentence does not say.** A receiver without
a fix keeps sending its last position in GGA and RMC; it is not published,
because a boat that drifted since is not where that says. GGA's fix quality 6
to 8 (dead reckoning, manual input, simulator) is not a fix either, and RMC
and VTG count only a mode indicator of A, D, F, R or P (autonomous,
differential, RTK float, RTK fixed, precise) as one, or no indicator at all
from a talker older than NMEA 2.3: a plotter left in simulator mode does not
put a made-up boat on the chart. GGA's altitude and geoid separation follow
the same rule as its position. An
empty field is a missing value, never a zero: a zero depth and a 0° heading
are values a consumer acts on.

Depth from DBT/DBS/DBK is taken in metres when the talker fills that field,
else in feet, else in fathoms, since sounders differ in which they send. DPT
carries the transducer offset, which is what places a sounding against the
waterline or the keel; a logger that needs to know where its soundings were
measured from should prefer DPT where the sounder offers both.

## GPS time

With `set_clock`, an RMC with a valid fix sets the device's clock through
`espos_time_set()` with the source `manual` ([time.md](time.md)): a device on
a boat with no internet then stamps its deltas with GPS time instead of
learning the time from the server first. It sets the clock once, and again
only when the two drift more than two seconds apart: a fix every second would
otherwise step the clock by the reception jitter every second, and timestamps
would run backwards. A clock SNTP set is left alone.

Only a valid RMC counts, and only from 2020 on. A receiver without a fix
reports its battery-backed clock, which after a GPS week rollover can be
twenty years out; ZDA alone is not trusted for the same reason. ZDA still
publishes `navigation.datetime`, since it has no status field to check and a
consumer can weigh it against the fix, but no `navigation.datetime` earlier
than 2020 is published from either sentence.

## Sending

With a `tx_gpio`, `espos_nmea0183_uart_write()` sends a sentence and adds its
checksum and CR LF. `espos_nmea0183_finish()` does the same into a buffer, for
a talker that sends over something else.

## When nothing arrives

`espos_nmea0183_uart_get_stats()` tells the usual faults apart:

| Reading | Means |
|---|---|
| `lines` stays 0 | no bytes, or no line endings: wrong pin, wrong baud, or the talker is off |
| `bad_checksum` climbs with `lines` | the bytes are wrong: baud rate, or an inverted line (`invert_rx`) |
| `rejected` climbs | lines that are not sentences: binary output (a u-blox module in UBX mode), or a talker without checksums with `require_checksum` set |
| `resyncs` climbs | sentences cut short: a noisy line, or a talker that restarts |
| `garbled` climbs | bytes that are not text inside a line: baud rate, a missing ground, or a binary protocol mixed in |
| `sentences` climbs, nothing in Signal K | the sentences are ones this component does not map; the listener still gets them |
